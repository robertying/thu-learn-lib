# Changelog

- v7.0.0 (unreleased)
  - (_BREAKING CHANGE_) `login` and `getRoamingTicket` take one `Credential` object instead of five positional arguments. `login(credential)` rejects with `NO_CREDENTIAL` when the credential lacks a username, a password or a fingerprint, instead of quietly falling back to the `CredentialProvider`; `login()` still uses the provider. `getRoamingTicket` rejects an incomplete credential with `NO_CREDENTIAL` too. Migration: `login(username, password, fingerPrint)` → `login({ username, password, fingerPrint })`, and the same for `getRoamingTicket`
  - (_BREAKING CHANGE_) Renamed types: `File` → `CourseFile` and `Notification` → `CourseNotification` (the old names shadow the DOM's `File` and `Notification`); `INotification` → `CourseNotificationBase`, `INotificationDetail` → `CourseNotificationDetail`, `IHomework` → `HomeworkBase`, `IHomeworkDetail` → `HomeworkDetail`, `IHomeworkStatus` → `HomeworkStatus`, `IExcellentHomework` → `ExcellentHomeworkBase`, `IHomeworkSubmitAttachment` → `HomeworkSubmitAttachment`, `IDiscussionBase` → `DiscussionBase`; `IHomeworkTA` and `IQuestionnaire` are gone (use `HomeworkTA` and `Questionnaire`, which were the same types). Migration: rename the imports; the shapes are unchanged
  - (_BREAKING CHANGE_) A JSON request retried after logging in again rejects with `UNEXPECTED_STATUS` when the retry's status is not 200, as text and plain requests already did, instead of returning its body. Migration: none needed unless you relied on a non-200 JSON body after a re-login
  - Errors stay plain `{ reason, extra }` objects (not `Error` instances), so code that compares `e.reason` or serializes errors keeps working
  - `@vitest/coverage-v8` and `pnpm test:coverage` for a coverage report
- v6.0.0
  - (_BREAKING CHANGE_) Every time field is a `ServerTime`: an ISO 8601 string in Beijing time with its offset (`2026-11-07T18:28:00+08:00`), which `new Date()` reads as the right moment in any time zone. The server's millisecond timestamps (homework `deadline`, `submitTime`, `lateSubmissionDeadline`, teacher homework and questionnaire times) and zone-less Beijing strings (notice, file, grade, discussion, favorite and comment times) are converted (a timestamp of 0, the server's "none", gives `undefined`); `FileCategory.creationTime` is a `ServerTime` instead of a `Date`. Semester and calendar dates stay date-only, and calendar `startTime` / `endTime` stay `HH:mm`
  - (_BREAKING CHANGE_) `Homework.excellentHomeworkList` is `[]` when a homework has no excellent homework, and `undefined` only when the course's excellent homework list couldn't be fetched
  - (_BREAKING CHANGE_) `Homework.favoriteTime` (always `undefined`) is removed; use `FavoriteItem.addedTime` from `getFavorites`
  - (_BREAKING CHANGE_) `getCourseList(..., { timeAndLocation: true })` leaves `timeAndLocation` out for a course whose request failed, instead of `[]`
  - (_BREAKING CHANGE_) Grade code -63 is `HomeworkGradeLevel.P` (was `PASS`, the same as -60)
  - (_BREAKING CHANGE_) A request that gets no answer at all (no connection, DNS or TLS failure) rejects with the new `FailReason.NETWORK_ERROR`, with the fetch error in `extra`, instead of the bare fetch error. `login` rejects with it, and with `REQUEST_TIMEOUT`, as they are instead of wrapping them in `ERROR_FETCH_FROM_ID`, so an offline device is told apart from a failing SSO server. `isConnectionError(e)` checks for either
  - `getHomeworkSubmitRequest` gives the request `submitHomework` sends (URL with the CSRF token, after checking the session, and the form), and `checkHomeworkSubmitResponse` reads the answer, for sending a submission with another HTTP client (e.g. for upload progress)
  - `submitHomework` takes a React Native file (`{ uri, type }`) as the attachment's `content`
  - `homeworkContentHtml` turns plain text into the HTML the website's answer editor sends
  - `parseCourseMeeting` reads an entry of `Course.timeAndLocation` (Chinese or English) into weekday, period, weeks and location; `CLASS_PERIOD_TIMES` gives the periods' times, `parseWeeks` reads a week spec, and `semesterWeek` counts teaching weeks from the term's first day
  - `getCalendar` logs in again (with the `CredentialProvider`) and tries once more when id.tsinghua.edu.cn turns the registrar sign-in down, as it does once the id.tsinghua.edu.cn session of the last login has expired
  - `addToFavorites`, `removeFromFavorites` and `setComment` succeed on `result: 'success'` alone, so they no longer reject with `OPERATION_FAILED` when the website is in English
  - `getHomeworkDetail`: a homework page with fewer attachment blocks no longer throws, and an empty description JSON falls back to the page's description instead of erasing it
  - Answered questions and teacher homework with an empty body no longer throw
  - `getCalendar` signs in to the registrar through WebVPN off campus (with the id.tsinghua.edu.cn session and fingerprints of the last `login`), and rejects with the new `FailReason.ERROR_REGISTRAR_AUTH` when that fails
  - `getCalendar` parses the registrar's JSONP as JSON instead of running it as code; registrar requests no longer carry the Web Learning CSRF token, and a registrar 403 no longer triggers a Web Learning re-login
  - `getFileListByCategory` (student) gives `isFavorite` as a boolean (it passed on the server's `'是'` / `'否'`)
  - Teacher files read `markedImportant` from a string `sfqd` too
  - `getUserInfo` gives `department: ''` when the English homepage shows "none"
  - The website language is read from the real homepage, so `getCurrentLanguage()` is right after `login` when the website is in English
  - `setLanguage` rejects with `OPERATION_FAILED` when the server refuses, instead of changing the language anyway
  - `getFileList` fetches the file list and categories in parallel
  - Upgrade cheerio to 1.2.0, tough-cookie to 6.1.0, fetch-cookie to 3.2.0 and entities to 9.0.0; `@types/tough-cookie` is no longer needed, as tough-cookie ships its own types
  - CI also tests on Node 22
  - A wrong password is recognised by the SSO login form coming back; other pages without the ticket link (a second factor, a locked account, maintenance) reject with `ERROR_FETCH_FROM_ID` instead of `BAD_CREDENTIAL`, and the ticket is read from the roaming link rather than from the first link on the page
  - After a `CredentialProvider` login is turned down with `BAD_CREDENTIAL`, automatic re-logins (an expired session, `ensureSession`) reject with it without asking id.tsinghua.edu.cn again, until the next explicit `login`
  - A 200 HTML page where JSON was expected counts as an expired session only when it is the login page (now also recognised by the real "login timeout" page's text); any other page rejects with `INVALID_RESPONSE` without a re-login
- v5.1.0
  - Treat a 200 HTML page where JSON was expected as an expired session: log in again and retry once, like a 403
  - `ensureSession` checks the probe's body (the current semester) instead of only its status
  - Logins never overlap: `login(username, password, fingerPrint)` waits for a login in progress, and requests that find the session expired during it wait for it instead of starting another SSO login
  - `submitHomework` with an attachment has no timeout (the response only starts after the upload)
  - A caller's `signal` can still cancel reading a body after the headers arrived
  - `getCalendar`: timed-out windows are not retried, and after two in a row the rest go to `failedRanges` without a request; an invalid date throws a `RangeError`; a bad JSONP body rejects with an `ApiError` (`INVALID_RESPONSE`) instead of a bare string
  - `getNotificationAttachment` returns `undefined` when the detail page has no attachment link, instead of throwing
  - `getHomeworkList(courseID, undefined, options)` type-checks; `getAllContents` rejects homework of a teacher course with `NOT_IMPLEMENTED` instead of returning student data
  - Supports Node 22 and later (was 26)
  - A wrong password rejects with `BAD_CREDENTIAL` (with the SSO page's message in `extra`) instead of `ERROR_FETCH_FROM_ID`, which now means the SSO server failed or couldn't be reached
  - HTML pages (user info, homework page, notice detail, calendar ticket) also detect the short login page of an expired session and log in again
  - `logout` forgets the CSRF token, so the next request logs in instead of sending the old token
  - `getFileList` still returns the files (without `category`) when the category list fails
  - `getQuestionnaireList(courseID, { details })` can skip the questions (one request per questionnaire; default still `'all'`), with `getQuestionnaireDetail(courseID, questionnaireID)` on demand; `detail` is now optional
  - Live tests need a fingerprint, use readable `.env` names (`USERNAME`, `PASSWORD`, `FINGERPRINT`, `STUDENT_SEMESTER`, …; see `test/live/template.env`) and cover session expiry and resume, on-demand details and windowed calendar
- v5.0.0
  - (_BREAKING CHANGE_) Per-item detail requests are opt-in: `getHomeworkList(id, CourseType.STUDENT, { details })`, `getNotificationList(id, type, { attachments })` (notices get `attachmentName`), `getCourseList(semester, type, lang, { timeAndLocation })` (`timeAndLocation` is now optional); fetch the rest on demand with `getHomeworkDetail`, `getExcellentHomeworkDetail`, `getNotificationAttachment` and `getCourseTimeAndLocation`
  - (_BREAKING CHANGE_) The excellent homework list is fetched once per course and comes without details
  - (_BREAKING CHANGE_) `getAllContents(ids, type, { courseType, details })` returns `{ contents, errors }` and no longer rejects when a course fails
  - (_BREAKING CHANGE_) `getCalendar(start, end, { graduate })` fetches ranges over 28 days in windows and returns `{ events, failedRanges }`
  - Requests are capped (`maxConcurrentRequests`, default 6) and time out (`requestTimeout`, default 60 s, `FailReason.REQUEST_TIMEOUT`); concurrent re-logins share one SSO login
  - `ensureSession()` resumes a saved session (CSRF token + cookies) and logs in only if it has expired
